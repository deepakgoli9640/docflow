# 08 — API Contracts

All public APIs are served through the gateway at `https://<host>/api/v1/...`. Each service also
publishes OpenAPI 3 docs (springdoc) at `/v3/api-docs` and Swagger UI at `/swagger-ui.html`
(disabled in the `prod` profile).

## 1. Cross-cutting conventions

| Concern | Convention |
|---|---|
| Versioning | URI major version: `/api/v1`. Additive changes stay in v1; breaking changes get `/api/v2` run side by side. URI versioning is chosen because it is explicit in logs, gateway routes and docs. |
| Auth | `Authorization: Bearer <JWT>` obtained from `POST /oauth2/token` (client credentials). Webhooks and checkout pages are the only unauthenticated routes and are protected by signatures / unguessable tokens. |
| Idempotency | `Idempotency-Key: <client-generated UUID>` **required** on `POST` that create or move money. Replays return `Idempotent-Replayed: true`. |
| Correlation | `X-Correlation-Id` accepted (validated: ≤ 64 chars, `[A-Za-z0-9-]`) or generated by the gateway; echoed on every response; in every log line and event. |
| Money | `{"amount": "20000.00", "currency": "INR"}` — amount is a **string** with exactly 2 decimals. |
| Time | ISO-8601 UTC, e.g. `2026-11-12T09:15:04Z`. |
| Pagination | `?page=0&size=20` (max 100). Response: `{ "content": [...], "page": {"number":0,"size":20,"totalElements":134,"totalPages":7} }`. Offset pagination is fine at these sizes; keyset (cursor) pagination is the documented upgrade for the transactions endpoint. |
| Sorting | `?sort=createdAt,desc` — only whitelisted fields per endpoint (unknown fields → 400, so clients can't trigger unindexed sorts). |
| Errors | RFC 9457 Problem Details (`application/problem+json`), see §7. |
| Tenancy | `merchant_id` always comes from the token, never from the URL or body for merchant APIs. Asking for another merchant's resource returns `404` (not `403`, to avoid confirming it exists). |

## 2. Merchant service

| Method | Path | Role | Success | Purpose |
|---|---|---|---|---|
| POST | `/api/v1/merchants` | public (rate-limited) | 201 | Register hospital → `PENDING_ACTIVATION`; returns first API key and webhook secret once |
| POST | `/api/v1/admin/merchants/{id}/activate` | OPS | 200 | Activate (or reactivate a suspended merchant); body `{"reason": "..."}` |
| POST | `/api/v1/admin/merchants/{id}/suspend` | OPS | 200 | Suspend: new tokens refused immediately; existing tokens refused by the gateway deny-list within seconds |
| GET | `/api/v1/admin/merchants/{id}/configuration` | OPS | 200 | A merchant's payment configuration (never the webhook secret) |
| POST | `/api/v1/admin/merchants/snapshots/republish` | OPS | 200 | Republish every merchant snapshot (rebuilds downstream replicas; safe to repeat) |
| POST | `/api/v1/admin/merchants/{id}/deactivate` | OPS | 200 | Permanent |
| GET | `/api/v1/admin/merchants?status=&page=&sort=` | OPS | 200 | List merchants (sort: createdAt, updatedAt, legalName, status) |
| GET | `/api/v1/admin/merchants/{id}` | OPS | 200 | One merchant |
| GET | `/api/v1/merchants/me` | MERCHANT | 200 | Profile |
| PATCH | `/api/v1/merchants/me` | MERCHANT | 200 | Update profile |
| GET / PUT | `/api/v1/merchants/me/configuration` | MERCHANT | 200 | Methods, limits, capture mode, TTL, webhook URL |
| POST | `/api/v1/merchants/me/api-keys` | MERCHANT | 201 | Create key; **secret returned once** |
| GET | `/api/v1/merchants/me/api-keys` | MERCHANT | 200 | List keys (masked) |
| DELETE | `/api/v1/merchants/me/api-keys/{keyId}` | MERCHANT | 204 | Revoke |
| POST | `/api/v1/merchants/me/webhook-secret/rotate` | MERCHANT | 200 | Rotate webhook signing secret (returned once) |
| POST | `/oauth2/token` | client credentials | 200 | Issue JWT (15 min) |
| GET | `/oauth2/jwks` | public | 200 | Public keys for JWT validation |
| GET | `/internal/v1/merchants/{id}/webhook-config` | SERVICE | 200 | For notification-service only; not routed by the gateway |

Platform maximums (per-transaction, daily, TTL range, attempts, refund window) are platform
configuration (`hpg.merchant.limits`); merchants choose values within them and anything above is
rejected with `422 LIMIT_EXCEEDS_PLATFORM_MAXIMUM`. A merchant can hold at most 2 active API keys
(enough for zero-downtime rotation) and cannot revoke its last active key. Samples:
[samples/http/merchant.http](../samples/http/merchant.http).

## 3. Payment service

| Method | Path | Role | Success | Purpose |
|---|---|---|---|---|
| POST | `/api/v1/payments` | MERCHANT | 201 | Initiate payment, create provider order |
| GET | `/api/v1/payments/{id}` | MERCHANT | 200 | Status and details |
| GET | `/api/v1/payments?status=&merchantReference=&from=&to=&page=&sort=` | MERCHANT | 200 | List |
| POST | `/api/v1/payments/{id}/capture` | MERCHANT | 200 | Capture an `AUTHORIZED` payment (full amount) |
| POST | `/api/v1/payments/{id}/cancel` | MERCHANT | 200 | Cancel before capture |
| GET | `/checkout/{checkoutToken}` | public | 200 | Hosted checkout page (loads Razorpay checkout) |
| POST | `/checkout/{checkoutToken}/callback` | public, signature-verified | 200 | Browser callback after payment |
| POST | `/webhooks/razorpay/payments` | public, signature-verified | 200 | Provider webhooks |

| POST | `/checkout/{checkoutToken}/simulate` | public | 200 | **Simulated provider only** (404 otherwise) |

Capture answers **202** with status `UNKNOWN` when the provider did not respond in time; the payment is
verified automatically and must not be captured again with a new key. Full samples:
[samples/http/payment.http](../samples/http/payment.http).

"Authorization" is not a merchant-callable endpoint: the **patient** authorizes the payment on the
provider's checkout. The merchant observes it (`AUTHORIZED` status / webhook) and then captures.

## 7. Errors

Shape (Spring `ProblemDetail` + extension properties): `type`, `title`, `status`, `detail`,
`instance`, `errorCode`, `correlationId`, `timestamp`, optional `violations[]`
(`{field, message}`) for validation errors.

| HTTP | `errorCode` examples | When |
|---|---|---|
| 400 | `VALIDATION_FAILED`, `INVALID_SORT_FIELD`, `MISSING_IDEMPOTENCY_KEY` | Bad input |
| 401 | `UNAUTHENTICATED` | Missing/invalid/expired token |
| 403 | `FORBIDDEN`, `MERCHANT_SUSPENDED`, `PAYMENT_METHOD_NOT_ENABLED` | Authenticated but not allowed |
| 404 | `PAYMENT_NOT_FOUND`, `REFUND_NOT_FOUND` | Not found **or not yours** |
| 409 | `INVALID_STATE_TRANSITION`, `DUPLICATE_PAYMENT`, `REQUEST_IN_PROGRESS`, `PAYMENT_NOT_YET_REFUNDABLE`, `DUPLICATE_SETTLEMENT_FILE` | Conflicts with current state |
| 422 | `IDEMPOTENCY_KEY_REUSED`, `AMOUNT_ABOVE_LIMIT`, `DAILY_LIMIT_EXCEEDED`, `REFUND_EXCEEDS_CAPTURED_AMOUNT`, `REFUND_WINDOW_EXPIRED` | Well-formed but violates a business rule |
| 429 | `RATE_LIMITED` | With `Retry-After` |
| 502 | `PROVIDER_REJECTED_CONFIGURATION` | Provider rejected our credentials/config (our fault, alert) |
| 503 | `SERVICE_UNAVAILABLE`, `PROVIDER_UNAVAILABLE` | DB down, circuit open on a call that cannot be deferred (e.g. capture) |

No stack traces, SQL, provider payloads or internal class names in error bodies — ever. Unexpected
exceptions return a generic 500 with the `correlationId` so support can find the log line.

## 8. Outgoing webhooks to hospitals

```http
POST {merchant webhook_url}
Content-Type: application/json
X-HPG-Event-Id: 01933f7e-6b1c-7c2a-9d4e-5f6a7b8c9d0e
X-HPG-Event-Type: payment.captured
X-HPG-Timestamp: 1794474904
X-HPG-Signature: v1=5c1f0e...   (hex HMAC-SHA256 of "<timestamp>.<raw body>" with the merchant's webhook secret)

{ "eventId": "...", "type": "payment.captured", "occurredAt": "2026-11-12T09:15:04Z",
  "sequence": 5,
  "data": { "paymentId": "...", "merchantReference": "BILL-2026-000981",
            "status": "CAPTURED", "amount": {"amount":"20000.00","currency":"INR"} } }
```

Hospital guidance (documented): verify signature, reject timestamps older than 5 minutes (replay
protection), dedupe by `X-HPG-Event-Id`, use `sequence` to ignore stale updates, respond `2xx`
within 10 s. We retry non-2xx with exponential backoff + jitter for up to 24 h, then mark the
notification `DEAD` and emit `NotificationFailed`.
